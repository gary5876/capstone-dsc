# DSC 6개 셀 — 평가지표·데이터셋·점수 산정 명세

DSC v5 framework의 6개 cell(2 task × 3 data_type)에 대해, 각 cell이 (A) 어떤 평가지표를 어떤 근거로 채택했는지, (B) 검증 실험에 어떤 데이터셋을 썼는지, (C) 모델 성능 점수를 어떻게 산정해 DSC와의 상관(r)을 냈는지를 정리한다. 모든 수치는 저장소 코드·실행 로그·결과 CSV로 확인한 값이며, 미측정/미실행 항목은 그렇게 표시한다.

근거 코드: `dsc_framework/` (각 `*_cell*.py`, `shared_metrics.py`), 오염 도구 `dq4ai/polluters/` + `dsc_framework/{image,text}_polluters/`. 근거 문서: `documents/decisions/ADR-002·009·011·012·014·015·016·017·018·019`, `documents/plans/20260427-02·20260511-01·20260528-01·20260530-01`, `documents/progress/20260602-01`, `documents/reports/20260522-01·20260603-01`. 근거 데이터: `results/`, 데이터셋 메타(컬럼타입·target·placeholder) `dq4ai/metadata.json`. 데이터셋 로드 코드: `notebooks/01_setup_and_baseline*.ipynb`, 정형 회귀 다운로드 `notebooks/_dev/download_regression_datasets.py`. 아래 각 셀 B의 출처·로드 방법은 모두 이 코드(=커밋된 실행 결과를 생성한 코드)에서 그대로 추출했다.

## 0. 6개 셀 공통 설계 원칙

셀별 표를 읽기 전에, 지표 구성을 결정하는 4개 원칙을 먼저 정리한다. 셀별 설명에서 반복하지 않는다.

### 원칙 1 — 절대 품질 지표로 교체 (ADR-009)

v3.2까지 최대 가중치(0.30)였던 `value_accuracy`(원본 대비 KS/TVD 분포 거리)를 제거했다. 이 지표는 baseline에서 항상 1.0이고 본질적으로 **drift(분포 변화) 측정 도구**일 뿐, "이 데이터가 학습에 좋은가"라는 절대 품질을 재지 못한다. 대신 ML 학습 가능성을 직접 재는 두 지표를 신설했다.

- `label_consistency`: k-NN(k=5) 이웃 라벨이 자기 라벨과 같은 비율(chance level 보정). 결정경계 모호도·라벨 노이즈를 직접 측정.
- `feature_informativeness`: 피처↔라벨 상호정보량(mutual information) / H(Y). 피처가 라벨을 설명하는 정도.

### 원칙 2 — task-conditional 강한 버전 (ADR-011)

같은 차원 이름이라도 `(data_type, task)`마다 **정의식(공식)이 다르다**. 예: `feature_correlation`은 tabular에서 컬럼 간 Pearson 상관, image에서 ResNet18 임베딩 차원 간 cosine 상관, text에서 DistilBERT 임베딩 차원 간 상관. 근거: 데이터 품질은 사용 목적에 따라 정의된다는 데이터 품질 문헌(Wang & Strong 1996, Pipino 2002), 동일 오염이 task별로 다르게 작용한다는 실증(Mohammed 2022/2025).

### 원칙 3 — 분류→회귀 3개 지표 치환

회귀 cell(정형·이미지·텍스트 공통)은 분류 cell에서 라벨을 전제하는 지표 3개를 target 기반으로 치환한다.

| 분류 지표 | 회귀 지표 | 정의식 변화 |
|---|---|---|
| `class_balance` | `target_distribution_quality` | target을 10-bin equal-width로 나눈 정규화 Shannon entropy (균일=1.0, 편향=0) |
| `label_consistency` | `target_smoothness` | k-NN(k=5) 이웃 target의 표준편차 / 전체 target 표준편차의 보수. 유사 샘플끼리 target이 비슷할수록 높음 |
| `feature_informativeness` | `feature_informativeness_reg` | `mutual_info_classif` → `mutual_info_regression` |

### 원칙 4 — 가중치 freeze 해제, 정의식만 freeze (ADR-015)

코드의 `DEFAULT_WEIGHTS_*`는 **fallback 값**이다. 운영·검증의 실제 가중치는 LLM 가중치 생성기(`llm_weight_generator.py`) 출력 또는 제약 최적화로 선정한다. 지표 정의식은 변경 시 ADR이 필요한 freeze 대상(순환논증 방지).

### 원칙 5 — 모델 성능 측정 프로토콜 (ADR-019, 6셀 통일)

> **"학습된 모델의 성능은 어떻게 평가했는가"에 대한 단일 답.** 셀별 `D. 모델 점수 산정`은 이 프로토콜을 각 모달리티에 적용한 결과다.

**측정 대상 정의.** DSC와 상관을 낼 종속변수는 "**오염된 학습 데이터로 학습한 모델이 깨끗한 테스트셋에서 내는 성능**"이다. 즉 DSC가 데이터 품질을 점수화하는 그 데이터로 모델을 실제 학습시켰을 때, 모델이 얼마나 잘 일반화하는가를 측정한다.

**(1) split-first + clean-test 평가 (데이터 누수 차단).** 각 데이터셋을 **먼저** train/test로 분할하고, 오염은 **train에만** 적용한다. 평가는 항상 **오염되지 않은 clean test set**에서 한다. 이렇게 해야 "더러운 학습 데이터가 모델을 얼마나 망가뜨리는가"를, 공정한 고정 벤치마크 위에서 분리 측정할 수 있다. test를 오염시키면 성능 하락이 "모델이 나빠진 것"인지 "채점 기준이 흔들린 것"인지 구분되지 않는다.

**(2) frozen-feature probe (주 측정법).** 모델 성능은 **고정 특징 위에 경량 모델을 얹어** 측정한다.

> **frozen-feature probe란.** 신경망을 두 부분으로 본다 — 입력을 벡터로 바꾸는 **backbone(특징 추출기)** 과 그 벡터로 예측을 내는 **head**. probe 방식은 사전학습된 backbone(ResNet18·DistilBERT)의 가중치를 **그대로 얼려(frozen, `requires_grad=False`, backprop 없이 forward만)** 임베딩 추출기로만 쓰고, 그 위에 얕은 head(여기선 sklearn Ridge/RandomForest/MLP/kNN)만 학습해 성능을 잰다. 즉 "무거운 backbone은 임베딩 함수로 고정, 그 임베딩 위 경량 모델만 학습"이다. 이것이 자기지도학습에서 표현 품질을 평가하는 표준 프로토콜인 **linear probing / linear evaluation**(SimCLR·MoCo·CLIP)이다.

- **고정 특징**: 정형 = 전처리된 컬럼 / 이미지 = frozen ResNet18 임베딩 / 텍스트 = frozen DistilBERT 임베딩. backbone은 학습하지 않고 forward만 한다(backprop 없음). 정형은 pretrained backbone이 없어 전처리 컬럼이 곧 특징이고, 그 위 sklearn 모델이 곧 실제 모델이다(정형 분류 셀 r=0.598이 이미 이 구조).
- **경량 모델 셋(task별 고정)**: 분류 = LogReg / RandomForest / MLP / kNN, 회귀 = Ridge / RandomForest / MLP / kNN. 선형·트리·신경망·거리기반으로 가설공간을 분산시켜, **상관이 특정 모델 한 종에 의존하지 않음**을 확인한다(셀별 D의 "모델별 양의 r" 판정).
- **점수**: 각 (dataset, polluter, level)의 오염된 train 특징으로 모델을 fit → clean test 특징에서 평가 → 모델들의 점수를 평균.
- 정형 분류 셀(r=0.598)은 pretrained backbone이 없어 이 sklearn 모델 자체가 곧 "실제 학습 모델"이며, 사전등록 당시 5종(+XGBoost·SVC)을 그대로 유지한다. ADR-019는 이 검증된 정형 프로토콜을 이미지·텍스트로 **확장·통일**한 것이다.

**한 config의 점수가 나오는 과정 (예: 이미지 회귀, UTKFace, polluter=blur, level=0.5).** 차원 512는 실제 코드 값(`image_cell.py`: ResNet18 `fc=Identity` → 512-d), R²·DSC 수치는 흐름 설명용 예시값.

```
1. train 이미지에 blur 0.5 적용                         → 오염된 train
2. 각 이미지를 ResNet18(ImageNet 가중치 frozen)에 1회 forward
   → avgpool 직전 512-d 벡터 = 임베딩
   결과: X_train = (N × 512),  y_train = 나이(연속)
3. Ridge.fit(X_train, y_train)                          ← 512→나이 회귀, <1초 CPU
4. clean test 이미지(오염 안 함)도 동일 ResNet18 forward → X_test
5. Ridge.predict(X_test) vs 진짜 나이 → R²=0.43(예시)
6. RandomForest·MLP·kNN도 2~5 반복 → 4종 평균 = 0.40(예시) = 이 config의 "모델 성능"
7. DSC 엔진도 같은 오염 train을 채점 → 85(예시)
   → 점 1개: (DSC=85, 성능=0.40)
```

이를 모든 (dataset × polluter × level)에 반복 → 점 수백 개 → 산점도 → Pearson r. **오염이 성능에 반영되는 원리**: probe를 *오염된 train*으로 학습시키므로(2~3단계), train이 흐리거나 라벨이 틀리면 학습 재료가 망가져 clean test 성능이 하락한다 — backbone이 frozen이어도 "오염이 학습을 망친 정도"는 그대로 측정된다. (텍스트는 ResNet18→DistilBERT, 512→768-d로 동일 구조.)

**(3) 왜 full finetune이 아니라 probe인가 (proxy 타당성).** 교수 예상 질문 핵심.

- **현실성**: full finetune은 (polluter × level × model)마다 GPU 학습을 요구해 6셀 전체로는 비현실적(이미지 회귀 단독 ~2.5h GPU, Colab 무료 한도 초과 반복). probe는 특징 1회 추출 + 건당 <1초 CPU fit → 셀당 수 분.
- **방법론적 정당성**: frozen feature 위 linear/light probing은 **표현학습의 표준 성능 평가법**(SimCLR·MoCo·CLIP). "데이터/표현의 사용 가능성"을 재는 인정된 척도다. 또 상관 연구에서는 finetune의 최적화 노이즈(init·lr·epoch 변동)를 제거해 **데이터 품질 효과를 더 깨끗이 분리**한다.

**(4) finetune spot-check (보조 — proxy가 실제 학습 성능을 따라간다는 입증).** backbone 1종(이미지 ResNet18 / 텍스트 DistilBERT)을 **DSC 범위를 가르는 축소 subset**(각 데이터셋 × {baseline + 최강신호 polluter × 5 level} ≈ 6 config)에서만 실제 finetune한다. 산출: r(probe성능, finetune성능)과 r(DSC, finetune성능) — 둘이 같은 방향이면 probe가 실제 학습 성능의 타당한 proxy임이 정량 입증된다.

> **현황 — 두 가지를 구분할 것.**
>
> - **실제 모델 학습(full finetune) 평가는 이미 존재한다.** 이미지 분류 셀은 ResNet18·EfficientNet 등을 **실제 10 epoch finetune**해 DSC↔성능 상관 r=0.449/0.447을 냈고(`results/model_performance_image.csv`, `epochs` 컬럼 = 실학습), 정형 두 셀은 sklearn 실모델 자체로 r=0.598/0.566을 냈다. 즉 "DSC가 진짜로 학습시킨 모델의 성능을 추종한다"는 증거는 probe 밖에서도 확보돼 있다.
> - **단, ADR-019식 spot-check(같은 셀·같은 config에서 probe와 finetune을 나란히 돌려 r(probe, finetune)을 산출)는 미실행이다.** 모든 perf CSV에 `method=='finetune'` 행이 0개이고, scoreboard 노트북이 "finetune spot-check 결과 없음(03 미실행)"을 출력한다(GPU 확보 시 실행 예정, progress 20260602-01 §121).
>
> **발표 방어선**: (a) 현 단계의 proxy 정당성은 (3)의 방법론적 근거(표현학습 표준 평가법) + **이미지 분류의 실제 finetune 상관(r≈0.45)** + 정형 셀(실모델, r=0.598)으로 방어한다. (b) probe↔finetune을 동일 config로 직접 대조하는 spot-check는 "예정"으로 표기하고, **그 r 수치를 "측정된 결과"로 제시하지 말 것.**

**(5) 성능 지표 선택 근거.**
- 분류 = **F1(macro)** 주력. `class_balance`가 polluter라 imbalance 상황이 의도적으로 발생하므로 accuracy는 다수 클래스에 가려져 오해를 부른다 → 클래스 평균 F1로 측정(accuracy·AUC는 보조).
- 회귀 = **R²**, 음수는 0으로 클립(baseline보다 나쁜 모델을 "0점 바닥"으로 처리해 음의 발산이 상관을 왜곡하지 않게 함).

**(6) 상관 산정 + held-out.** (dataset × polluter × level × model) 조합마다 (DSC Score, 모델 성능) 쌍을 만들고 전체에서 **Pearson r**(보조 Spearman)을 잰다. 일반화는 두 held-out으로 확인: **LODO**(leave-one-dataset-out, 학습에 안 쓴 새 데이터셋) + **LOPO**(leave-one-polluter-out, 안 본 새 오염유형).

> **표본 1점의 단위는 셀마다 다르다(혼동 주의).** 두 가지 방식을 쓴다 — ① **모델별 점**: 각 (config × model)을 독립 표본 1개로 본다(정형 분류 n=435, 정형 회귀 n=324, 텍스트 dev n=30). ② **모델평균 점**: 한 config의 여러 모델 성능을 평균해 config당 1점으로 본다(이미지 회귀 — probe 4종 평균, dataset별 26점). ①은 모델 다양성까지 상관에 반영하고, ②는 모델 간 분산을 지워 데이터셋 단위 신호를 깨끗이 본다. 또 **상관선의 모집단 단위**도 다르다 — 정형·텍스트는 데이터셋을 pool한 전체가 헤드라인 r(단일 회귀선), 이미지는 데이터셋마다 성능 대역이 달라(배치효과) **데이터셋별 r·회귀선**이 정본이다(pool하면 희석). 셀별 `D`에 각 단위를 명시한다.

**한계(발표 limitations에 명시).** probe 성능은 "고정 표현 위 성능 proxy"로 full-finetune 성능보다 좁은 개념이고, ImageNet/대규모 코퍼스 사전학습 backbone은 일부 오염에 강건해 해당 오염의 성능 저하를 과소평가할 수 있다(정형은 backbone 없어 무관). 실제로 이미지 회귀 검증에서 frozen ResNet18 임베딩이 가우시안 노이즈에 민감해 probe가 붕괴하는데도 DSC는 평평한 blind spot이 드러났고, 이를 `signal_integrity` 메트릭 신설(Immerkær σ 추정)로 보강했다(셀 3·4, ADR-019 §8). 이런 과소평가 위험은 finetune spot-check가 부분 보정·방어한다.

### 공통 사항 — label_consistency / target_smoothness 가 0.20 최고 가중치인 이유

이 지표가 "유사한 입력이 유사한 출력을 갖는가"라는 **학습 가능성의 핵심**을 직접 재기 때문이다. 정형 분류 제약 최적화에서도 이 지표가 0.30으로 최상위에 오르며, "ML 학습가능성 직결 지표가 품질을 주도한다"는 서사를 데이터가 뒷받침한다(plan 20260530-01 §2-5).

### 점수 산정 파이프라인 (모든 셀 동일)

```
DSC Score = Σ(지표ᵢ × 가중치ᵢ) × 100  → 등급 A(≥90)/B(≥75)/C(≥60)/D(<60)

검증: train/test split-first → train만 오염 → frozen 특징(컬럼/ResNet18/DistilBERT) 추출
      → 경량 probe 모델 4종(task별) fit → clean test 평가 → 성능 점수 평균   (= 원칙 5)
      → (dataset × polluter × level × model) 조합마다 (DSC Score, 성능) 쌍
      → DSC Score ↔ 성능 Pearson r 측정 (분류=F1 macro, 회귀=R²)
보조: finetune spot-check(축소 subset) → r(probe성능, finetune성능)로 proxy 타당성 입증
held-out: LODO(leave-one-dataset-out, 새 데이터셋 일반화)
          LOPO(leave-one-polluter-out, 새 오염유형 일반화)
```

전 셀 공통 합격선: held-out Pearson r ≥ 0.40 (정형 분류만 r ≥ 0.50, v4 baseline 기준).

### C. 오염 방법 — DQ4AI polluter 5종 (정형 전용)

정형 데이터 오염은 HPI 연구실의 **DQ4AI**(Data Quality for AI, ScienceDirect 2025)를 그대로 사용한다(ADR-002 — 학술 검증·정형 전문·우리 데이터셋이 `dq4ai/metadata.json`에 이미 정의되어 즉시 사용). 각 polluter는 **단 하나의 품질 차원만 망가뜨리고 나머지는 보존**하도록 설계되어, "그 차원이 떨어질 때 모델 성능이 얼마나 하락하는가"를 분리 측정할 수 있다. target 컬럼은 오염에서 제외하며, metadata에 등록된 random seed 5개로 반복한다.

**정형 데이터에서 "오염"이란** — 한 행은 *(feature 컬럼 값들) + (라벨)* 이고, 표 전체로는 *(행 구성)*·*(표기 일관성)* 속성이 더해진다. 오염은 이 중 하나만 골라 망가뜨린다: 셀 값을 비우거나(결측)·틀리게 하거나, 같은 행을 중복으로 채우거나, 같은 뜻을 다른 표기로 쪼개거나, 클래스 비율을 무너뜨린다.

아래 표에서 **변형 방식**은 코드가 실제로 하는 처리(기술 설명), **모사하는 현실 문제**는 그게 흉내 내는 현실의 데이터 사고(직관 설명)다.

| polluter (차원) | 도구 | 오염 대상 | 변형 방식 (코드가 하는 일) | 모사하는 현실 문제 |
|---|---|---|---|---|
| completeness | DQ4AI | feature 값(삭제) | target 제외 feature 셀 중 level 비율을 placeholder로 치환해 값을 비움(수치형 `-1`, 범주형 `'missing'`). 이미 결측인 셀은 빼고 추가 | 입력 누락·미기입 |
| feature_accuracy | DQ4AI | feature 값 | 수치형: 표준편차 level인 Gaussian noise를 컬럼 평균 스케일로 더해 값을 틀어뜨림. 범주형: level 비율 샘플을 다른 카테고리로 교체(이진은 0↔1 반전) | 센서 오차·입력 오류 |
| uniqueness | DQ4AI | 행 구성(중복) | 중복 제거 후 같은 행을 복제 주입(클래스 비율 유지, `uniqueness=1/duplicate_factor`) | 중복 수집·로그 중복 |
| consistent_repr | DQ4AI | 표기 일관성 | 범주값에 의미는 같고 표기만 다른 변형을 섞음(문자열 `값-1`/`값-2`, 정수 max+i 코드), level 비율 행에 적용 | `Male`/`M`/`male`처럼 표기 불일치 |
| class_balance | DQ4AI | 클래스 구성 | 균형 baseline에서 클래스별 샘플을 차등 제거해 imbalance 유발(정렬 시 직선형 분포) | 특정 클래스만 많이 수집된 편향 |

level 그리드(`results/model_performance.csv`, 435건 실측): pollution **6단계** {0.1, 0.25, 0.5, 0.75, 0.9, 0.95} + baseline(0.0).

### D. 모델 점수 산정

- 모델 5개: LogisticRegression, RandomForest(n=100), XGBoost(n=100), SVC(linear), MLP(5층). 정형은 pretrained backbone이 없어 **전처리된 컬럼이 곧 특징이고 이 sklearn 모델 자체가 곧 "실제 학습 모델"**이다(원칙 5(2): probe=실모델, finetune 무관).
- 성능 지표: F1(macro) 주력 (accuracy·AUC 보조)
- **산정 절차 (한 점이 만들어지는 과정).** ① 각 (dataset, polluter, level) config의 **오염된 train**으로 5개 모델을 각각 독립 학습(`.fit`) → ② 오염 안 한 **clean test**에서 각 모델의 F1(macro) 산출 → ③ 이미지 회귀처럼 모델을 평균하지 **않고**, **각 (config × model) 쌍을 표본 1점**으로 산점도에 올린다. 점 1개 = (그 config의 DSC Score, 그 모델의 F1). → ④ 전체 점에서 Pearson r.
- **표본 수**: n=435 = **87 config × 5 model**(87 = 3 dataset × [polluter·level 그리드 + baseline]의 실측 합, `results/merged_results.csv`). 산점도 회귀선은 3개 데이터셋 pool 단일선(헤드라인).
- 결과(정식 v4): **Pearson r=0.598**(pool), Spearman 0.628, 등급별 ANOVA F=84.4, RF 5-fold 비선형 R²=0.632. 데이터셋별 letter r=0.80(강), Telco·Credit r≈0.24~0.28(약) — 데이터셋별로 보면 letter가 상관을 견인. 6개 셀 중 유일하게 정식 held-out 통과.

| polluter | 도구 | 오염 대상 | 변형 방식 (코드가 하는 일) | 모사하는 현실 문제 |

### C. 오염 방법 — 자체 구현 5종 (DQ4AI 미지원)

DQ4AI는 정형 데이터 전용(ADR-002)이라 이미지에 못 쓴다. 따라서 5종 polluter를 **전부 자체 구현**했다(`dsc_framework/image_polluters/`, ADR-014). numpy/cv2 기반, 공통 인터페이스 `pollute(images, labels) → (images, labels)`, seed 고정으로 재현.

**이미지에서 "오염"이란 무엇을 건드리는가** — 한 장의 이미지 데이터는 *(픽셀 배열) + (라벨)* 로 이루어지고, 데이터셋 전체로는 *(클래스 구성)* 이라는 속성이 추가된다. 오염은 이 셋 중 **하나만** 골라 의도적으로 망가뜨린다. 그래서 polluter는 "픽셀을 흐리거나·노이즈를 얹거나·일부를 지우는 것", "정답 라벨을 틀리게 바꾸는 것", "특정 클래스 사진을 솎아내 구성을 무너뜨리는 것" 세 부류로 나뉜다. 각 변형은 현실에서 실제로 일어나는 데이터 품질 사고를 흉내 낸 것이다.

아래 표에서 **변형 방식**은 코드가 실제로 하는 처리(기술 설명), **모사하는 현실 문제**는 그게 흉내 내는 현실의 데이터 사고(직관 설명)다.

| polluter | 도구 | 오염 대상 | 변형 방식 (코드가 하는 일) | 모사하는 현실 문제 |
|---|---|---|---|---|
| blur | 자체 | 픽셀 | 전 이미지에 `sigma = level × 5.0` Gaussian blur 적용(cv2, 없으면 scipy) — 선명도를 떨어뜨림 | 초점 안 맞은·저해상도·흔들린 사진 |
| noise_injection | 자체 | 픽셀 | 전 이미지에 `std = level × (이미지 std)`인 Gaussian noise를 더한 뒤 [0,255] 클립 — 픽셀 값을 지직거리게 함 | 저조도 센서 노이즈·압축/전송 손상 |
| completeness_image | 자체 | 픽셀(삭제) | level 비율의 이미지를 골라 면적 30% 직사각형을 검정(0)으로 덮음 — 이미지 일부를 지움 | 가림(occlusion)·센서 결함·잘린 이미지 |
| label_swap | 자체 | 라벨 | 픽셀은 그대로, level 비율의 정답 라벨만 무작위 다른 클래스로 교체 | 주석자(annotator) 라벨링 실수 |
| class_balance | 자체 | 클래스 구성 | majority 클래스는 유지, 나머지 클래스 사진을 `(1-level)` 비율로 undersample — imbalance 유발 | 특정 클래스만 많이 수집된 편향 |

즉 같은 "level 0.5"라도 blur는 *흐림 강도*, completeness는 *지운 이미지 비율*, label_swap은 *틀린 라벨 비율*, class_balance는 *소수 클래스 축소율*로 의미가 다르다. level 그리드(`results/model_performance_image.csv` 실측): pollution **5단계** {0.1, 0.3, 0.5, 0.7, 0.9} + baseline ≈ 26 config/데이터셋.

### D. 모델 점수 산정

- **측정 방식이 다른 유일한 셀 — 실제 full finetune.** 이 셀의 r=0.449/0.447은 ADR-019 probe 재설계 *이전*에 backbone 전체를 실제 학습시켜 낸 값이다(다른 5셀은 probe 또는 sklearn 실모델). 향후 probe로 통일 시 재측정 예정이나, **현 수치는 "오염 train으로 실제 finetune한 모델의 clean test 성능"**이라 proxy 논쟁에서 가장 강한 근거(원칙 5(4) 방어선).
- 사전등록 모델은 5종(ResNet18·EfficientNetB0·MobileNetV3-small·ViT-Tiny·CNNSimple)이나, **실제 실행·상관에 쓰인 모델은 2종**: **ResNet18(pretrained) + CNNSimple(scratch)**, 각 **10 epoch finetune**(`results/model_performance_image.csv`의 `epochs=10` 컬럼이 실학습 증거). 나머지 3종 미실행.
- 성능 지표: accuracy
- **산정 절차**: config의 오염 train으로 두 backbone을 각각 10 epoch 학습(backbone 포함 전체 가중치 갱신) → clean test accuracy → **각 (config × model) 쌍이 표본 1점**. dataset별 n = **26 config × 2 model = 52점**.
- **상관 단위 = 데이터셋별**(두 데이터셋의 accuracy 대역이 달라 pool 부적절): default **CIFAR-10 r=0.449 / Fashion-MNIST r=0.447**(둘 다 합격선 PASS). 참고로 pooled r=0.389(희석). LLM 튜닝 가중치 적용 시 0.504 / 0.578로 상승. 정식 full held-out 미수행.
