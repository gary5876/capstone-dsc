# 캡스톤 발표자료 구성 계획

> 긴 발표(~26장) 기준 구성안. 1단계(말할 내용 모으기) → 2단계(페이지 나누기)까지의 산출물.
> 3단계(각 페이지 실제 내용·자료 채우기)는 이 골격 확정 후 진행.

---

## 0. 서사 방향 (framing)

- **전제**: 처음부터 6셀 framework를 목표로 했다는 흐름으로 구성.
- **중심 서사**: ① **왜 시작했나** + ② **어쩌다 이 DSC framework가 됐나**.
- 엔진 실패→수정(r=0.085 → 0.598)은 숨기는 장면이 아니라, **"왜 framework가 task-conditional·reference-free·사전등록 구조가 됐는지"를 설명하는 핵심 장면**으로 배치. 단순한 단일 점수가 실제로 깨진 경험이 곧 *어쩌다 이렇게 됐나*의 근거.
- **정직성 원칙**: 결과 수치는 정식으로 제시하되 측정 기준(데이터셋·모델·held-out)을 함께 표기. 6셀 전부 상관 확인(정식).

## 1. 말할 수 있는 내용 (재료 메뉴)

### A. 한 줄 정의 + 가설
- DSC = 데이터셋을 받아 [0,100] 품질점수 + 등급(A/B/C/D)을 내는 함수.
- 핵심 가설 H₁: "DSC 점수가 그 데이터로 학습한 ML 모델 성능과 통계적으로 유의하게 같이 움직인다." 본질은 점수 정의가 아니라 그 점수가 성능과 함께 움직임을 실증하는 것(실패하면 DSC는 임의의 숫자).

### B. 의미·기여
1. 가중치를 의미 있게 정하고 held-out 일반화로 검증 — 가중치는 튜닝 데이터셋에서 최적화하되, 한 번도 안 본 held-out 데이터셋·polluter와 합격선을 **미리 선언한 뒤 1회 검증**. 튜닝셋에서 잡은 가중치가 unseen에서도 상관을 재현하면 그 가중치가 의미 있다는 증거(ML train/test 분리와 동일).
2. 학습 가능성을 직접 재는 reference-free 지표 — label_consistency(k-NN), feature_informativeness(mutual info)로 "이 데이터로 모델이 학습 가능한가"를 데이터 하나로 측정(운영 환경엔 reference 없음 — 교수 지적 해소).
3. Task-conditional 강한 버전 framework — `(데이터유형, 태스크) → {지표셋, 가중치}` 매핑. 기존 도구는 데이터셋의 이용 목적(태스크)을 고려하지 않음(task-agnostic).
4. 검증이 정의를 개선한 사례 — 성능측정 재설계중 노이즈 맹점 발견 → signal_integrity 신설로 held r 0.42→0.94.

### C. 작업물 (6셀 매트릭스)
| 셀 | 상태 | 비고 |
|---|---|---|
| 정형 분류 | 정식 통과 | 엔진 검증의 본진 |
| 이미지 회귀 | 정식 통과 | held-out까지 완료 |
| 이미지 분류 | 정식 통과 | held-out = Fashion-MNIST(운영 held-out) |
| 텍스트 분류 | 정식 통과 | full sweep 3종(ag_news·imdb·20news) 3/3 PASS, probe |
| 텍스트 회귀 | 정식 통과 | full sweep 3종(yelp·amazon·sst5) 3/3 PASS, probe |
| 정형 회귀 | 정식 통과 | r=0.566, hold-out 5/5, 4모델(SVR 제외) |

+ 검증 인프라: split-first, 오염 sweep(유형별 polluter 5~7종 × level), held-out 사전등록, polluter hold-out, 단조성 검증, 비트단위 동일성 검증.

### D. 결정과 이유 — 스토리라인
1. 인프라 확정: Colab+Drive, 오염도구 DQ4AI, 데이터셋/모델을 의도적으로 분산(우연 차단).
2. 엔진 결함 발견 → v2→v3.2→v4 ★클라이맥스: r=0.085 실패 → 슬라이스 부호 정반대(정의 결함) → 두 버그 수정 → 초기 테스트에서 상관 가능성 확인(r=0.42) → held-out·합격선을 미리 선언한 본 실험으로 정식 검증 → r=0.598.
3. Task-conditional framework 재정의: 단일 점수 → framework, 강한 버전 채택.
4. LLM 가중치 생성기로 검증 framing 재정의: "신호 존재 증명" → "메커니즘 acceptance test".
5. 멀티모달 셀 사전등록: 미러 패턴으로 6셀 매트릭스.
6. 성능측정 재설계(최신): full finetune → frozen-feature probe로 6셀 통일 → 노이즈 blind spot 발견·해결.

### E. 결과 수치 (측정 기준 표기)
- 정형 분류(정식, n=435): r=0.598(p=1.6e-43), 비선형 RF R²=0.632, polluter hold-out 5/5 PASS, 등급별 F1 단조(A 0.88→D 0.52). v3.2 0.42 → v4 0.598.
- 정형 회귀(정식, n=324): r=0.566(p≈7e-29), Spearman 0.569, 비선형 RF 5-fold R²=0.538, polluter hold-out 5/5 PASS, 4모델(SVR 제외).
- 이미지 회귀(정식, held-out SCUT): default r=0.668, 제약최적 가중치 r=0.951.
- 이미지 분류(정식, held-out=Fashion-MNIST): r=0.45(튜닝 시 0.578).
- 텍스트(정식 full sweep, probe 기반, 각 3 데이터셋, 2026-06-04): 분류 ag_news 0.676 / imdb 0.412 / 20news 0.613, 회귀 yelp 0.555 / amazon 0.503 / sst5 0.487 — 둘 다 3/3 PASS. (dev finetune 선행검증 0.643/0.404는 폐기)

### F. 한계·남은 과제
- 합성 오염 한정, baseline=원본 가정, r²=0.358 → "예측"이 아닌 "상대 비교/랭킹/모니터링" 용도.

### G. 수행 방법 · 지표 설계 · 가중치 (선정 이유 / live·dead / 왜 0.05)

- **수행 방법 (전 셀 공통 파이프라인)**: split-first(train/test 분리 → train만 오염, test는 clean 유지) → frozen 특징 추출(정형=전처리 컬럼, 이미지=ResNet18 임베딩, 텍스트=DistilBERT 임베딩) → 경량 probe 모델 4종 fit → clean test 성능 측정(분류 F1 macro, 회귀 R²) → (데이터셋×오염종류×강도×모델) 조합마다 (DSC, 성능) 쌍 → Pearson 상관 r. held-out은 두 종류 — 새 데이터셋 일반화(한 데이터셋을 빼고 학습)·새 오염유형 일반화(한 오염을 빼고 학습). 보조로 일부 구간 full finetune을 같이 돌려 probe가 실모델 성능의 타당한 proxy임을 확인.
- **각 지표 선정 이유**: 지표는 품질 차원 1개씩에 대응하되, 핵심은 *학습 가능성을 직접 재는* 지표 — `label_consistency`(k-NN 라벨 일치율)·`target_smoothness`("유사 입력→유사 출력인가")·`feature_informativeness`(특징→라벨 상호정보량)에 최고 가중치(0.20). reference 데이터가 있어야 계산되던 옛 지표(value_accuracy)를 제거하고 이들로 교체한 게 v4의 핵심. 가중치 최적화에서도 label_consistency가 최상위로 올라 "학습가능성 직결 지표가 품질을 주도"를 데이터가 뒷받침.
- **live / dead 지표**: 표준 벤치마크는 이미 정제돼 있어 `validity·consistency·feature_correlation·uniqueness·outlier_ratio`가 baseline부터 거의 1.0(변동 없음) → 상관에 기여 못 함(**dead**). 반면 `label_consistency·completeness·sample_quality·class_balance·feature_informativeness`는 오염 강도따라 변동(**live**). 이미지·텍스트에서도 같은 5/5 구도가 재현됨.
- **왜 0이 아니라 0.05 (확정 서사)**: dead 지표는 clean 데이터에서 값이 상수 → 점수에 **상수 오프셋**만 더함 → DSC↔성능 상관 r엔 영향 없음(affine 변환). 그래서 r만 보면 0으로 보내도 되지만, **0으로 죽이지 않는 이유**는 ① 실세계 더러운 데이터에선 발화하는 유효한 품질 차원이라 "데이터 품질 점수"로서 차원을 유지해야 변호 가능, ② 순수 r 최대화는 outlier_ratio에 0.48이 몰리는 식의 변호 불가한 가중치를 낳기 때문. → **0.05 = 차원을 죽이지 않으면서 상관엔 영향 안 주는 최소 오프셋.** (정확히는 0.05가 설계상의 하한이 아니라 v4에서 미리 정한 손가중치 기본값으로, 현 검증 엔진에 실재하며 r=0.598을 만든 현행 값. 운영 가중치는 LLM 생성기가 정하고 허용범위가 0.01~0.60이라 0.05에 고정되지 않음.)

- **P14b 지표 선정 — 각 지표가 무엇을 재는가** — [메시지] 9개 지표가 각각 품질 차원 1개에 대응하되, label_consistency(kNN)·feature_informativeness(MI)는 "이 데이터로 학습 가능한가"를 직접 측정해 최고 가중치(0.20). 차원별 매핑 + 가중치 배분 근거 / [자료] 지표→차원→가중치 표
- **P15 정식 결과 r=0.598** — [메시지] r=0.598(p=1.6e-43, n=435), 비선형 R²=0.632, polluter hold-out 5/5, 등급별 F1 단조 / [자료] 회복된 산점도 + 등급별 F1 막대
