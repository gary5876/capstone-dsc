### P5 — 우리의 비전: 6셀 framework
- 핵심 문구: (데이터유형 3 × 태스크 2) = 6셀. 각 셀이 `(유형, 태스크) → {지표셋, 가중치}` 매핑
- 표시 요소: 6셀 매트릭스
  - 행 = 데이터유형(정형 / 이미지 / 텍스트), 열 = 태스크(분류 / 회귀)
  - 각 셀: 지표 9~11개 + 셀별 가중치. 공통 골격(completeness·uniqueness·validity·consistency·outlier·feature_correlation) + 분류/회귀 치환(class_balance↔target_distribution_quality, label_consistency↔target_smoothness, feature_informativeness↔feature_informativeness_reg)
  - 강한 버전 원칙: **차원 이름이 같아도 정의식은 셀마다 다름** (예: feature_correlation = 정형 컬럼 Pearson / 이미지 ResNet18 임베딩 cosine / 텍스트 DistilBERT 임베딩 cosine)
- 자료: 6셀 매트릭스 다이어그램(핵심 비주얼, 신규 제작)

## 막 2. 어떻게 증명할 것인가 — 검증 설계

### P7 — 오염 실험 설계
- 핵심 문구: DQ4AI polluter로 데이터를 강도별로 오염 → (DSC, 성능) 쌍 수백 개 수집
- 표시 요소: 오염 sweep 도식
  - polluter 5종(결측·중복·값왜곡·표현불일치·분포왜곡) × level 다단계 + baseline
  - 정형 분류: 3 데이터셋 × (5×4 + baseline) × 5 모델 = **n=435**
  - 이미지/텍스트: 5종 × 5단계 + baseline = 26 config/데이터셋
  - 각 config마다 (DSC 점수, 모델 성능) 쌍 1개 생성
- 자료: (신규 도식)

### P8 — 학술적 안전장치
- 핵심 문구: 결과에 휘둘리지 않게 4중 안전장치 — split-first / 가중치 사전등록 / polluter hold-out / 자동 leakage 검증
- 표시 요소: 파이프라인 도식
  - ① split-first: clean을 train/test 분할 후 **train에만 오염**, test는 clean 유지
  - ② 자동 검증: 학습 직전 train↔test 겹침 검사, 발견 시 RuntimeError로 중단
  - ③ 가중치 사전등록: 결과 보기 전에 고정 (순환 논증 차단)
  - ④ polluter hold-out: 특정 오염을 빼고 학습해 새 오염 유형 일반화 확인
- 자료: (신규 도식)

### P17 — LLM 가중치 생성기
- 핵심 문구: 운영 시 LLM이 메타데이터(스키마·통계·분포 요약)만 보고 1분 내 가중치 생성. **실측 라벨·오염 정보는 차단**(overfitting 방지)
- 표시 요소: 생성기 흐름 — 입력(유형·태스크·메타데이터) → LLM → 가중치 dict → JSON schema 검증(합=1, 각 w∈[0.01,0.60]) → 실패 시 사전등록 fallback
- 자료: (신규 흐름도)

### P18 — 튜닝/held-out 분리
- 핵심 문구: 가중치는 튜닝 데이터셋에서만 정하고, r은 held-out에서 1회만 측정 → 측정 후 그 데이터셋은 튜닝셋으로 강등(재사용 금지) → cherry-picking 자동 차단 (ML train/val/test 원리)
- 자료: (신규 도식)

### P19 — 성능측정 통일 (probe)
- 핵심 문구: 모델 full finetune은 6셀 × 수백 config에 비현실적 → **frozen-feature probe**로 통일
- probe 한 줄 정의: pretrained backbone을 **얼려서(가중치 안 건드림) 임베딩 추출기로만** 쓰고, 그 임베딩 위에 **가벼운 모델(Ridge/RF/MLP/kNN)만 학습**해 성능을 잼 = 자기지도학습 표준 평가법 **linear probing**(SimCLR·CLIP)
- 표시 요소 ①: 데이터 흐름 도식 (한 config)
  - `오염 train 이미지 → frozen ResNet18 (forward만) → 임베딩(512-d) → Ridge.fit → clean test 임베딩으로 평가 → 점수`
  - 오염이 점수에 반영되는 이유: probe를 **오염된 train**으로 학습 → 학습 재료가 망가져 clean test 성능 하락 (backbone 고정이어도 "오염이 학습을 망친 정도"는 잡힘)
- 표시 요소 ②: 트랙 비교
  - 정형: backbone 없음 → 전처리 컬럼이 곧 특징, sklearn 모델이 곧 실제 모델 (LR/RF/XGB/SVC/MLP)
  - 이미지·텍스트: pretrained 임베딩(ResNet18 / DistilBERT) freeze + 경량 probe(Ridge/RF/MLP/kNN)
  - 성능 = probe 평균 (분류 accuracy / 회귀 R²). ridge가 가장 반응성 좋아 운영 권장
- 왜 finetune이 아닌가(2줄): (a) GPU 비용 — config당 수 분 × 수백 = 비현실적, probe는 임베딩 1회+CPU fit으로 셀당 수 분 / (b) finetune의 최적화 노이즈(lr·init·epoch)를 제거해 **데이터 품질 효과만 분리**
- 자료: (신규 도식 — 데이터 흐름 + 트랙 비교)
