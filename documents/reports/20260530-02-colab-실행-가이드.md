## 0. 시작 전 체크 (가장 중요)

1. **Drive 동기화 확인 (1순위 함정).** 로컬(G드라이브 마운트)에서 방금 만든 새 파일들이 **Google Drive 클라우드에 완전히 업로드된 뒤** Colab을 열 것. 동기화 전이면 Colab이 새 코드를 못 본다.
   - 새로 만든 것: `dsc_framework/image_cell_regression.py`, `dsc_framework/image_polluters/target_distribution_skew.py`·`target_noise.py`, `notebooks/01~04_*_image_regression.ipynb`
   - 확인법: drive.google.com 웹에서 해당 파일이 보이는지, 또는 G드라이브 데스크톱 앱 동기화 완료 표시.
2. **런타임 유형**: 이미지·텍스트 트랙은 **GPU(T4) 필수** (Runtime → Change runtime type → T4 GPU). 정형(tabular) 트랙은 sklearn이라 CPU로도 됨.
3. **경로 전제**: 모든 노트북이 `BASE = /content/drive/MyDrive/capstone/dsc`를 가정. Drive에서 `capstone` 폴더가 이 경로에 있어야 함.

## 1. 공통 주의점 (모든 노트북)

- **첫 셀에서 `drive.mount`** → 계정 인증 팝업. 매 새 런타임마다.
- **의존성 설치 셀(`%pip install ...`)을 반드시 실행.** 런타임이 새로 뜨면 매번 다시 깔아야 함.
  - 이미지: `timm imagehash opencv-python-headless` (+ 이미지 회귀는 `datasets`)
  - 정형: `xgboost`
- **`dsc_framework` 못 찾는다는 에러**가 나면 Drive 동기화 미완. 이미지 노트북엔 `force_remount` 자동복구 셀이 있으니 그 셀 실행. 그래도 안 되면 동기화 기다렸다 런타임 재시작.
- **트랙별 순서 엄수: `01 → 02 → 03 → 04`** 순차 실행.
  - 02가 폴루션 데이터를 Drive에 저장 → 03이 읽음. 04가 02(DSC)+03(성능) 결과를 합쳐 분석. 순서 어기면 빈 데이터로 실패.

## 3. 처음 돌리는 노트북 특별 주의 (정형회귀·이미지회귀)

이 두 트랙은 **한 번도 끝까지 실행된 적 없다**(결과 파일 없음). 대량 실행 전에 **01부터 돌려 베이스라인이 정상인지 먼저 확인**:

- **정형 회귀 `01_regression`**: 베이스라인 DSC가 나오는지 (예: California Housing ≈ 89점대). DQ4AI는 이미 repo에 있어 clone 스킵됨.
  - `02_regression` 함정: `uniqueness` polluter가 행을 최대 6배 복제 → California에서 SVR 학습이 느림(Colab이라 OK, 시간만 소요). split-first(train만 오염, test clean) 이미 적용됨.
- **이미지 회귀 `01_image_regression`**: HF에서 **UTKFace(~884MB)·SCUT 다운로드**(첫 실행 시 시간 소요). 베이스라인 DSC + age/beauty 분포 확인.
  - HF rate limit 경고가 뜨면 `HF_TOKEN` 설정으로 완화 가능(선택, 필수 아님).
  - `02/03_image_regression`이 무거움(ResNet18 임베딩 + 모델 학습) → **GPU 필수**.
  - ⚠️ 로컬엔 torchvision이 없어 이 노트북들은 **Colab이 첫 실전 실행**이다. 01에서 임베딩 경로(target_smoothness 등)가 정상 나오는지 꼭 확인 후 02~03 진행.

## 6. 실행 후 확인할 것

각 트랙 04 노트북 출력에서:
- **dataset별 Pearson r ≥ 0.40** (합격 단위, `plans/20260511-01`)
- **polluter hold-out** 통과 비율 (순환논증 방지)
- **held-out 가중치 r** (default vs 제약최적) — 이미지 회귀는 UTKFace 튜닝 / SCUT held-out

값이 나오면 정형 분류(r=0.598)처럼 해당 셀의 정식 결과로 확정. 결과 CSV가 Drive에 저장되면 로컬에서도 분석 가능.

## 7. 예상 소요시간

**조건**: 이미지=Colab T4 GPU, 정형=Colab CPU. 이미지 회귀 `SAMPLE_CAP=2000`(OOM 수정 후). Phase 1 설정(이미지: 모델 2종·EPOCHS 10·5레벨·2데이터셋 / 정형: 모델 5종·6레벨·3데이터셋). 노트북마다 새 런타임 → HF 데이터셋 재다운로드(~10분) 고정비 가정.

### 이미지 회귀 (T4 GPU)
| 노트북 | 내용 | 예상 |
|---|---|---|
| `01_..._image_regression` | HF 다운로드 + 베이스라인 DSC | ~10~15분 |
| `02_..._image_regression` | 다운로드 ~10분 + 52 config × 임베딩 DSC(2000장) | ~20~30분 |
| `03_..._image_regression` | 104 학습(2000장·10ep, ~1분/건) | ~1.5~1.75시간 |
| `04_..._image_regression` | 상관 + 가중치 선정 | ~2분 |

→ **합계 ~2.5~3시간** (01 포함). 병목 = `03` 학습. 근거: 2000÷batch128≈16 step/ep × 10 = 160 step, T4 ResNet18 ~0.2~0.4s/step → ~1분/건 × 104 ≈ 90분.

### 정형 회귀 (CPU)
| 노트북 | 내용 | 예상 |
|---|---|---|
| `01_..._regression` | 로드 + 베이스라인 | ~5분 |
| `02_..._regression` | split+오염+DSC (81 config, 임베딩 없어 빠름) | ~15분 |
| `03_..._regression` | 모델 5종 × 81 = 405 학습 | ~2~4시간 |
| `04_..._regression` | 상관 + 차트 | ~2분 |

→ **합계 ~2.5~4.5시간**. 병목 = `03`의 **SVR** (`uniqueness` 오염이 California 행을 최대 6배 복제 → SVR O(n²)이 고레벨에서 건당 수~수십 분). 이 한 지점이 2시간이냐 4시간이냐를 가른다.

### 종합
- **순차**: ~5~7.5시간
- **병렬**(정형 CPU 세션 + 이미지 GPU 세션 동시): 느린 쪽(정형 ~2.5~4.5h)에 수렴 → **반나절이면 둘 다 결과 CSV 완료**

### 변수
- 다운로드(~10분/노트북)가 고정비. 같은 세션에서 연속 실행 시 HF 캐시 재사용으로 단축.
- 이미지 2000에서도 OOM이면 1000으로 → `03` 학습 ~절반(~45분).
- 무료 티어 GPU 한도·90분 idle·12시간 세션 주의. `03`은 체크포인트라 끊겨도 이어감 → **Pro 권장**.
- FULL 설정(이미지 5모델·30ep·6레벨)으로 돌리면 이미지가 5~10배(~1일+). 현재 노트북은 Phase 1 축소라 위 추정 적용.
