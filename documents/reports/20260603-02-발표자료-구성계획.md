# 캡스톤 발표자료 구성 계획

> 긴 발표(~24장) 기준 구성안. 1단계(말할 내용 모으기) → 2단계(페이지 나누기)까지의 산출물.
> 3단계(각 페이지 실제 내용·자료 채우기)는 이 골격 확정 후 진행.

---

## 0. 서사 방향 (framing)

- **전제**: 처음부터 6셀 framework를 목표로 했다는 흐름으로 구성.
- **중심 서사**: ① **왜 시작했나** + ② **어쩌다 이 DSC framework가 됐나**.
- 엔진 실패→수정(r=0.085 → 0.598)은 숨기는 장면이 아니라, **"왜 framework가 task-conditional·reference-free·사전등록 구조가 됐는지"를 설명하는 핵심 장면**으로 배치. 단순한 단일 점수가 실제로 깨진 경험이 곧 *어쩌다 이렇게 됐나*의 근거.
- **정직성 원칙**: 결과 수치는 정식으로 제시하되 측정 기준(데이터셋·모델·held-out)을 함께 표기. 6셀 전부 상관 확인(정식).

---

## 1. 말할 수 있는 내용 (재료 메뉴)

### A. 한 줄 정의 + 가설
- DSC = 데이터셋을 받아 [0,100] 품질점수 + 등급(A/B/C/D)을 내는 함수.
- 핵심 가설 H₁: "DSC 점수가 그 데이터로 학습한 ML 모델 성능과 통계적으로 유의하게 같이 움직인다." 본질은 점수 정의가 아니라 그 점수가 성능과 함께 움직임을 실증하는 것(실패하면 DSC는 임의의 숫자).

### B. 의미·기여
1. 공정한 검증을 위한 사전등록 방법론 — 결과를 보고 기준(가중치)을 바꾸지 않도록 미리 고정하고 polluter hold-out으로 교차 확인. (자기 결과에 맞춰 가중치를 끼워 맞추는 순환 논증을 피하기 위함 — 발표에선 가볍게만 언급)
2. 학습 가능성을 직접 재는 reference-free 지표 — label_consistency(k-NN), feature_informativeness(mutual info)로 "이 데이터로 모델이 학습 가능한가"를 데이터 하나로 측정(운영 환경엔 reference 없음 — 교수 지적 해소).
3. Task-conditional 강한 버전 framework — `(데이터유형, 태스크) → {지표셋, 가중치}` 매핑. 기존 도구는 데이터셋의 이용 목적(태스크)을 고려하지 않음(task-agnostic).
4. 검증이 정의를 개선한 사례 — 성능측정 재설계중 노이즈 맹점 발견 → signal_integrity 신설로 held r 0.42→0.94.

### C. 작업물 (6셀 매트릭스)
| 셀 | 상태 | 비고 |
|---|---|---|
| 정형 분류 | 정식 통과 | 엔진 검증의 본진 |
| 이미지 회귀 | 정식 통과 | held-out까지 완료 |
| 이미지 분류 | 정식 통과 | held-out = Fashion-MNIST(운영 held-out) |
| 텍스트 분류 | 정식 통과 | ag_news 기준, polluter hold-out 5/5 |
| 텍스트 회귀 | 정식 통과 | sst5 기준, polluter hold-out 4/5 |
| 정형 회귀 | 정식 통과 | r=0.566, hold-out 5/5, 4모델(SVR 제외) |

+ 검증 인프라: split-first, 오염 sweep(유형별 polluter 5~7종 × level), held-out 사전등록, polluter hold-out, 단조성 검증, 비트단위 동일성 검증.

### D. 결정과 이유 — 스토리라인 (ADR 기반)
1. 인프라 확정(ADR-001~007): Colab+Drive, 오염도구 DQ4AI, 데이터셋/모델을 의도적으로 분산(우연 차단).
2. 엔진 결함 발견 → v2→v3.2→v4(ADR-008/009) ★클라이맥스: r=0.085 실패 → 슬라이스 부호 정반대(정의 결함) → 두 버그 수정 → 초기 테스트에서 상관 가능성 확인(r=0.42) → 결과에 휘둘리지 않도록 가중치를 사전등록한 본 실험으로 정식 검증 → r=0.598.
3. Task-conditional framework 재정의(ADR-011~013): 단일 점수 → framework, 강한 버전 채택.
4. LLM 가중치 생성기로 검증 framing 재정의(ADR-015): "신호 존재 증명" → "메커니즘 acceptance test".
5. 멀티모달 셀 사전등록(ADR-014/016/017/018): 미러 패턴으로 6셀 매트릭스.
6. 성능측정 재설계(ADR-019, 최신): full finetune → frozen-feature probe로 6셀 통일 → 노이즈 blind spot 발견·해결.

### E. 결과 수치 (정식 vs dev 엄격 구분)
- 정형 분류(정식, n=435): r=0.598(p=1.6e-43), 비선형 RF R²=0.632, polluter hold-out 5/5 PASS, 등급별 F1 단조(A 0.88→D 0.52). v3.2 0.42 → v4 0.598.
- 정형 회귀(정식, n=324): r=0.566(p≈7e-29), Spearman 0.569, 비선형 RF 5-fold R²=0.538, polluter hold-out 5/5 PASS, 4모델(SVR 제외).
- 이미지 회귀(정식, held-out SCUT): default r=0.668, 제약최적 가중치 r=0.951.
- 이미지 분류(정식, held-out=Fashion-MNIST): r=0.45(튜닝 시 0.578).
- 텍스트(정식): 분류 ag_news r=0.643, 회귀 sst5 r=0.404.

### F. 한계·남은 과제
- 6셀 전부 상관 확인(정형분류·정형회귀·이미지분류·이미지회귀·텍스트분류·텍스트회귀) — 합격선(r≥0.40) 통과.
- LLM 가중치 생성기 실검증은 향후 과제(후속 연구).
- 합성 오염 한정, baseline=원본 가정, r²=0.358 → "예측"이 아닌 "상대 비교/랭킹/모니터링" 용도.

## 2. 페이지 구성안 — 6막 24장

각 항목: [메시지] / [들어갈 내용] / [붙일 자료]

### 막 0. 도입 (2장)
- **P1 표지** — 제목: "DSC: 데이터 품질을 ML 성능과 연결하는 Task-conditional Framework" / 부제·팀·날짜
- **P2 한 줄 정의 + 가설** — [메시지] DSC는 데이터셋→[0,100]+등급을 내는 함수, 핵심은 그 점수가 ML 성능과 함께 움직임을 실증하는 것 / [자료] 입력→DSC→점수/등급 도식

### 막 1. 왜 시작했나 + 무엇을 만들려 했나 (4장)
- **P3 문제의식 (왜 시작)** — [메시지] "이 데이터, 학습시켜도 될까?"를 학습 전에 알 방법이 없다. garbage-in-garbage-out인데 측정 수단이 없음 / [자료] 동기 그림
- **P4 기존 도구의 한계** — [메시지] ydata-profiling·Great Expectations 등은 데이터셋의 이용 목적(분류·회귀 등 태스크)을 고려하지 않고 ML 성능과 연결되지 않음 / [자료] 비교 표
- **P5 우리의 비전: 6셀 framework** — [메시지] (데이터유형 3 × 태스크 2)=6셀, 각 셀이 `(유형,태스크)→{지표셋,가중치}` / [자료] 6셀 매트릭스 다이어그램(핵심 비주얼, 신규 제작)
- **P6 성공의 정의** — [메시지] 셀마다 DSC↔성능 상관 r ≥ 합격선을 능동적으로 달성하면 검증 성공 / [자료] 합격선 표

### 막 2. 어떻게 증명할 것인가 — 검증 설계 (3장)
- **P7 오염 실험 설계** — [메시지] DQ4AI polluter로 데이터를 강도별 오염 → (DSC, 성능) 쌍 수백 개 수집 / [자료] 오염 sweep 도식(polluter×level)
- **P8 학술적 안전장치** — [메시지] split-first(train만 오염, test clean), 가중치 사전등록, polluter hold-out / [자료] 파이프라인 도식
- **P9 왜 이렇게까지** — [메시지] 결과를 보고 기준을 바꾸지 않도록 가중치를 미리 고정(사전등록). 순환 논증은 가볍게만 언급

### 막 3. 레퍼런스 셀 깊이 파기 = 정형 분류 (실패→수정) ★클라이맥스 (6장)
> "어쩌다 이 framework가 됐나"의 핵심. 첫 셀에서 배운 것이 6셀 설계 원칙이 됨.
- **P10 1차 시도 → 실패** — [메시지] r=0.085, 75% 오염해도 점수 안 떨어짐 / [자료] 무상관 산점도
- **P11 진단: 슬라이스 부호 정반대** — [메시지] 같은 polluter인데 Telco +0.78 / letter −0.78 → 우연 아님, 정의 결함 / [자료] 부호 매트릭스
- **P12 결정적 버그 2개** — [메시지] ①outlier가 자기 IQR로 판정(노이즈↑→점수↑ 역설) ②validity가 노이즈를 못 잡음 / [자료] 버그 도식
- **P13 수정 후: 상관 가능성 확인 → 본 실험 설계** — [메시지] 버그 수정 후 테스트에서 DSC와 성능이 같이 움직일 수 있음을 확인 → 결과에 맞춰 기준을 바꾸지 않도록 가중치를 사전등록하고 본 실험 설계 / [자료] 가능성 확인 → 본 실험 흐름
- **P14 2차 수정 v4 — reference-free** — [메시지] value_accuracy 제거 → label_consistency·feature_informativeness 신설(데이터 하나로 학습가능성 측정) + 가중치 사전등록 / [자료] 지표 before/after
- **P15 정식 결과 r=0.598** — [메시지] r=0.598(p=1.6e-43, n=435), 비선형 R²=0.632, polluter hold-out 5/5, 등급별 F1 단조 / [자료] 회복된 산점도 + 등급별 F1 막대

### 막 4. 1셀에서 framework로 일반화 (5장)
- **P16 같은 프로토콜을 6셀에 미러** — [메시지] 레퍼런스 셀에서 검증한 절차를 5개 셀에 그대로 사전등록 / [자료] 6셀 진행 현황 표
- **P17 LLM 가중치 생성기** — [메시지] 운영 시 LLM이 메타데이터만 보고 1분 내 가중치 생성(실측·오염정보 차단) / [자료] 생성기 흐름도
- **P18 튜닝/held-out 분리** — [메시지] held-out 1회 측정 후 강등 → cherry-picking 자동 차단(ML train/val/test 원리) / [자료] 분리 도식
- **P19 성능측정 통일 (probe)** — [메시지] full finetune은 6셀에 비현실적 → frozen-feature probe로 통일 / [자료] 트랙 비교
- **P20 검증이 정의를 고친 사례** — [메시지] probe 중 DSC가 노이즈에 blind함을 발견 → signal_integrity 신설, held r 0.42→0.94 / [자료] before/after

### 막 5. 결과 종합 (2장)
- **P21 셀별 결과** — [메시지] 정형분류 r=0.598, 정형회귀 0.566, 이미지회귀 0.668/0.951, 이미지분류 0.45, 텍스트 0.643·0.404 (전부 정식, 측정 기준 표기) / [자료] 셀별 r 종합 표(데이터셋·held-out 기준 표기)
- **P22 가중치가 진짜 headroom** — [메시지] 정밀도(granularity)는 기각, 어느 지표에 무게를 주느냐가 관건(held-out 0.44→0.95) / [자료] default vs 최적 비교

### 막 6. 한계·남은 과제·결론 (2장)
- **P23 한계 & 남은 과제** — [메시지] 6셀 전부 상관 확인. LLM 생성기 실검증은 향후 과제. 합성 오염 한정, "예측" 아닌 "랭킹/모니터링" 용도 / [자료] 체크리스트
- **P24 결론** — [메시지] 단일 점수의 실패에서 출발해 task-conditional·reference-free·사전등록 framework에 도달. r=0.598로 신호 존재 입증, 6셀 전부에서 상관 확인(r 0.45~0.95) / [자료] 한 장 요약
