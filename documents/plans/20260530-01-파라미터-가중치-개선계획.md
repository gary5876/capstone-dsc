# 파라미터·가중치 개선 계획

> 발표 준비 과정에서 "우리가 정한 파라미터·가중치가 의미 있다"를 입증하려다 드러난
> 약점들을 앞으로의 작업 계획으로 정리한다. 모든 수치는 저장소 데이터로 실측 검증.

---

## 0. 핵심 진단 — 무엇이 부족한가

발표용으로 점검한 결과, 현재 상태의 약점은 **가중치 정밀도(granularity)가 아니라** 다음 세 군데다.

1. **가중치 값 자체가 최적이 아님** — 손으로 정한 0.05 grid 가중치는 정형 분류에서 r=0.598인데, 같은 데이터로 최적화하면 held-out r=0.70까지 오른다. 성능을 남겨두고 있다.
2. **여러 지표가 "dead"** — 표준 벤치마크에서 uniqueness·validity·feature_correlation·consistency가 baseline부터 ≈1.0이라 상관에 기여 못 함. 최적화는 이들 가중치를 0으로 보냄.
3. **target_smoothness의 floor effect** — 텍스트 회귀에서 baseline부터 0.226으로 낮은데 최고 가중치(0.20)를 받음. 오염을 줘도 더 안 떨어짐.

그리고 **검증 자체가 미완**: 5개 셀 중 정식 held-out을 통과한 건 정형 분류 1개뿐.

---

## 1. 가중치 granularity 가설은 기각 (실측 완료)

가설: "가중치를 0.05 → 0.02 단위로 잘게 하면 r이 오른다."
정형 분류(n=435, merged_results.csv)에서 직접 검증:

| 항목 | r (in-sample) | r (held-out, leave-one-dataset-out) |
|---|---:|---:|
| 현재 가중치 (0.05 grid) | 0.598 | 0.437 |
| 최적화 — 연속값 | 0.791 | 0.703 |
| 최적화 — 0.05 grid 스냅 | 0.790 | 0.692 |
| 최적화 — 0.02 grid 스냅 | 0.791 | 0.707 |
| 최적화 — 0.01 grid 스냅 | 0.791 | — |

**결론:**
- 0.05 → 0.02 grid의 r 차이는 **+0.001** (in-sample). 강건성 테스트: 현재 가중치를 ±0.02 무작위 섭동 100회 시 r std=0.013 → 0.02 정밀도는 측정 노이즈 바닥 아래.
- 향상의 원천은 grid 해상도가 아니라 **어느 지표에 가중치를 주느냐**(값 자체).
- 따라서 **granularity 세분화는 추진하지 않는다.** 대신 §2의 가중치 선정 절차에 집중.

> ⚠️ 단, 순수 r 최대화 가중치는 `outlier_ratio=0.48`로 쏠리고 `completeness=0`·`uniqueness=0`이 됨. 숫자만 좋고 "데이터 품질 점수"로서 변호 불가. r 극대화와 해석 가능성은 트레이드오프 — §2가 이를 다룬다.

## 2. 가중치 선정 절차 정립 (최우선)

목표: **성능과 상관되면서 동시에 해석 가능한** 가중치를, 재현·변호 가능한 절차로 선정.

- **2-1. 튜닝/held-out 분리 고정.** 가중치는 튜닝 데이터셋에서만 정하고, r은 held-out에서만 보고. (정형 분류는 §2-4에서 제약 최적화 시 LODO 0.44→0.61로 일반화 확인 — 절차가 작동함을 입증.)
- **2-2. 해석 가능성 제약 추가.** 순수 r 최대화 대신, 가중치에 도메인 제약을 건다. 예: completeness·label_consistency 같은 "학습 가능성 직결" 지표에 하한(예 ≥0.10)을 두고, outlier_ratio 같은 약신호 지표에 상한(예 ≤0.15). 제약 하 최적 r과 무제약 r의 격차를 "해석 가능성의 비용"으로 보고.
- **2-3. 결과 보고 형식.** 각 셀마다 (현재 가중치 r) / (제약 최적 가중치 held-out r) / (무제약 천장 r) 3개를 같이 제시 → "우리 가중치는 천장 대비 X% 지점이며 해석 가능하다"는 정량 주장 확보.
근거 데이터: `results/merged_results.csv`(정형분류), `results/text_dsc_sweep.csv`+`text_train_metrics_dev.csv`(텍스트), `results/dsc_scores_image.csv`+`model_performance_image.csv`(이미지).

### 2-4. 실행 결과 (2026-05-30, 4개 셀)

제약: 각 가중치 ∈ [0.02, 0.35], 핵심 지표(completeness*·label_consistency/target_smoothness) 하한 0.10. held-out 두 종류 — **LODO**(leave-one-dataset-out, 新 데이터셋 일반화), **LOPO**(leave-one-polluter-out, 新 오염유형 일반화).

| 셀 | n | 데이터셋 | 현재 r (in-sample) | 제약최적 r | 천장 r | LODO 현재→최적 | LOPO 현재→최적 |
|---|---:|---:|---:|---:|---:|---|---|
| 정형 분류 | 435 | 3 | **0.598** | 0.764 | 0.791 | 0.437 → **0.608** | 0.694 → 0.702 |
| 이미지 분류 | 104 | 2 | **0.389** | 0.550 | 0.630 | 0.448 → 0.409 | 0.116 → 0.439 |
| 텍스트 분류(dev) | 30 | 1 | **0.643** | 0.773 | 0.792 | — | 0.642 → 0.636 |
| 텍스트 회귀(dev) | 30 | 1 | **0.404** | 0.481 | 0.630 | — | 0.423 → 0.377 |
| 정형 회귀 | — | — | 결과 파일 없음 (미실행) | — | — | — | — |

**충실성 검증:** 4개 셀 모두 현재-가중치 in-sample r이 프로젝트 기보고 수치와 일치(정형분류 0.598, 이미지 pooled 0.389, 텍스트분류 0.643, 텍스트회귀 0.404) → 최적화 수치 신뢰 가능.

**해석 (단순하지 않음 — 데이터 양이 가른다):**
- **in-sample은 항상 오른다**(천장 0.63~0.79) — 당연(자유도↑). 단독으로는 근거 못 됨.
- **新 데이터셋 일반화(LODO)는 데이터가 충분할 때만 이득.** 정형분류(3 dataset, n=435)에서만 0.44→0.61로 **과적합 없이 실제 상승** + 가중치도 해석 가능(label_consistency 0.30, completeness 0.10). 이게 발표 가능한 유일한 깔끔한 승리.
- **이미지(2 dataset)는 LODO에서 오히려 하락**(0.45→0.41) — CIFAR↔FMNIST dataset shift가 커 한쪽서 정한 가중치가 전이 안 됨. 텍스트(1 dataset, n=30)는 LOPO 평탄/하락 — 표본 부족으로 결론 불가.
- **즉 병목은 가중치 정밀도가 아니라 데이터(셀당 데이터셋 수·표본).** 정형분류처럼 데이터가 쌓인 셀에서만 "제약 최적화로 해석 가능하면서 held-out r 상승"을 입증할 수 있다.

**남은 해석 이슈:** 제약 최적에서도 정형분류 `outlier_ratio`가 0.34로 최상위. "데이터 품질 점수에서 outlier가 최대 비중"은 변호가 약함 → 약신호 지표에도 상한(예 ≤0.15)을 거는 추가 제약 검토 필요(§3과 연계). → §2-5에서 실행.

### 2-5. 최종 제안 가중치 — 정형 분류 (완전 해석가능 제약, 2026-05-30)

약신호·형식 지표(`outlier_ratio`·`validity`·`feature_correlation`) 상한 0.15 추가, 핵심(`completeness`·`label_consistency`) 하한 0.10. 전체 데이터로 선정 후 **0.05 grid 반올림**(granularity 무의미 확인 — 반올림해도 r 0.7435→0.7453로 동일).

| 지표 | 제안(0.05 grid) | 현재 |
|---|---:|---:|
| **label_consistency** | **0.30** | 0.20 |
| outlier_ratio | 0.15 | 0.05 |
| completeness | 0.10 | 0.20 |
| validity | 0.10 | 0.05 |
| consistency | 0.10 | 0.10 |
| feature_correlation | 0.10 | 0.05 |
| class_balance | 0.05 | 0.10 |
| feature_informativeness | 0.05 | 0.10 |
| uniqueness | 0.05 | 0.15 |

(연속 최적값을 0.05로 정리. label_consistency가 최상위 = "ML 학습가능성 직결 지표가 품질을 주도"라는 일관된 서사.)

**성능 (정형 분류):**

| 가중치 | in-sample r | LODO held-out r |
|---|---:|---:|
| 현재(손으로 정한) | 0.598 | 0.437 |
| 제안(완전 제약·해석가능) | 0.745 | **0.58~0.60** |
| (참고) 약제약 | 0.764 | 0.608 |
| (참고) 무제약 천장 | 0.791 | 0.703 |

→ **해석 가능성의 비용 = held-out r 약 0.10**(천장 0.70 → 완전제약 0.58~0.60). 그래도 손으로 정한 현재(0.44)보다 **+0.14** 높고, 가중치가 변호 가능. 발표에 그대로 올릴 수 있는 결과.

**남은 흠집 2개(정직히 기록):** (1) `outlier_ratio`가 상한 0.15에 핀처럼 붙음 — 데이터가 더 높은 값을 원함. 진짜 신호인지 letter 데이터셋 구조 confound인지 §3·§5에서 규명. (2) `uniqueness`·`class_balance`·`feature_informativeness`가 0.05로 바닥 — 클린 벤치마크에서 dead라 최적화가 가중치를 거의 안 줌(§3 논점과 일치). 이는 결함이 아니라 "이 셀에서 신호를 내는 지표가 무엇인지"의 측정 결과.

## 3. Dead 지표 정리

표준 벤치마크에서 거의 1.0 고정이라 상관에 기여 못 하는 지표(uniqueness·validity·feature_correlation·consistency)를 어떻게 변호/처리할지 결정.

- **3-1. 두 갈래 결정.** (a) 유지하되 "실세계 더러운 데이터에서는 발화한다"를 별도 실험으로 입증 — 의도적으로 더러운 real-world 샘플 1~2개에서 이들 지표가 떨어지고 성능도 떨어지는지 확인. 또는 (b) 셀별로 dead 지표 가중치를 명시적으로 낮추고 그 근거를 기록.
- **3-2. Live/Dead 표 공식화.** §2 보고에 "이 셀에서 어떤 지표가 신호를 내는가"를 명시 → 가중치 0 부여가 임의가 아니라 측정 결과임을 보임.

근거: `documents/reports/20260515-02-이미지-cell-지표-테스트-정리.md`, 본 발표자료 §3-4.

## 4. target_smoothness floor effect (텍스트/정형 회귀)

- **4-1. baseline 정상화.** 텍스트 회귀 sst5에서 baseline target_smoothness=0.226. 원인 분석: 작은 샘플(200~)·임베딩 이웃 target 분산이 본래 큰 데이터 특성인지, 공식 문제인지 구분. sample_cap·k 값 민감도 sweep.
- **4-2. 가중치 재고.** floor에 걸린 지표가 최고 가중치(0.20)를 갖는 구조 점검 → §2 제약 최적화에서 자동 조정되는지 확인.

근거: `results/text_dsc_sweep.csv`(target_noise sweep에서 0.226→0.246, 하락 안 함).

## 5. 검증 매트릭스 완성 (5개 셀)

| 셀 | 현재 상태 | 다음 작업 |
|---|---|---|
| 정형 분류 | ✅ 정식 r=0.598 | §2 제약 최적화 적용해 held-out r 갱신 |
| 정형 회귀 | ⏳ 데이터셋만 등록(California/Bike/Wine) | 베이스라인·오염·상관 정식 1회 실행 |
| 이미지 분류 | 🔶 Phase 1(default r=0.45) | 정식 full held-out, §2 절차로 가중치 |
| 텍스트 분류 | 🔶 dev r=0.643 | 정식 full held-out sweep |
| 텍스트 회귀 | 🔶 dev r=0.404 | 정식 full held-out sweep + §4 |

- **5-1. 데이터셋 수 확대.** held-out 주장이 현재 정형 3개·이미지 2개·텍스트 dev에 의존. leave-one-dataset-out의 통계적 힘이 약함(데이터셋 n이 작음). 셀당 데이터셋을 늘려 일반화 주장 강화.
- **5-2. 약신호 데이터셋 처리.** Telco·Credit은 held-out r이 불안정([0.23, 0.29] vs letter 0.80). ADR-010/012의 한계·degradation index를 발표에 명시하거나, 강신호 데이터셋 비중 조정.

## 6. 발표 메시지 재정렬

위 작업이 끝나면 발표 주장은 다음으로 정리:

1. **파라미터 설계의 정당성** — 각 지표는 ML 학습 가능성을 직접 측정(label_consistency·target_smoothness·feature_informativeness). task별 정의식 재정의(강한 버전, ADR-011).
2. **가중치의 정당성** — granularity가 아니라 **튜닝/held-out 분리 + 해석 가능성 제약**으로 선정. "천장(r=0.79) 대비 해석 가능한 지점(r=0.70)을 택했다"는 정량 근거.
3. **일반화 입증** — leave-one-dataset-out에서 가중치가 과적합 없이 일반화됨(0.44→0.70).
